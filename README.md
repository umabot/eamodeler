# EAModeler

A Python toolkit for Enterprise Architect reporting, reconciliation, and documentation automation.

## Overview

EAModeler provides practical utilities for working with Enterprise Architect exports and related CSV inventories. It helps teams reconcile interface lists, generate Markdown documentation with Mermaid diagrams, and transform source files into reusable artifacts.

### New in this branch

A new `mdw-ricefw-diff` command compares `MDW-FLOW` and `RICEFW` inventories and generates a Markdown reconciliation report showing:
- `OK` items found in both files
- `EXTRA` items found only in `MDW-FLOW`
- `MISSING` items found only in `RICEFW`

Looking for interface reconciliation between MDW and RICEFW files? See [MDW vs RICEFW Diff](#mdw-vs-ricefw-diff).

## Setup

This project uses [uv](https://docs.astral.sh/uv/) for package management with a virtual environment at `~/development/uv/eamodeler`.

### Prerequisites

- Python 3.12+
- uv package manager

### Quick Setup (Recommended)

The easiest way to set up the environment is to use the provided setup script:

```bash
./setup-env.sh
```

This script will:

- Create the virtual environment at the correct location if it doesn't exist
- Install all project dependencies
- Install development dependencies
- Verify the installation
- Provide usage instructions

### Manual Setup

If you prefer to set up manually:

1. Clone the repository:
   ```bash
   git clone <repository-url>
   cd eamodeler
   ```

2. Create the virtual environment:
   ```bash
   uv venv --python 3.12 ~/development/uv/eamodeler
   ```

3. Install the project and dependencies:
   ```bash
   VIRTUAL_ENV=~/development/uv/eamodeler uv pip install -e .
   VIRTUAL_ENV=~/development/uv/eamodeler uv pip install -e ".[dev]"
   ```

4. Activate the environment:
   ```bash
   source ~/development/uv/eamodeler/bin/activate
   ```

### Using the Environment

Once set up, you can use the tools in several ways:

1. With the environment activated:
   ```bash
   source ~/development/uv/eamodeler/bin/activate
   uv run eamodeler --help
   ```

2. Using the `run.sh` helper script (recommended):
   ```bash
   ./run.sh eamodeler --help
   ./run.sh eamodeler mdw-ricefw-diff input/MDW-FLOW.csv input/RICEFW_2026-03-30.csv
   ```

3. Using `uv run` directly:
   ```bash
   uv run eamodeler gen-interface-docs input/MDW-FLOW.csv APP_0100 --direction target --country UK
   ```

## Input/Output Directories

### input/
Place your source files in the `input/` directory for processing by EAModeler tools:
- CSV files - Data tables and model information
- Excel files (.xlsx, .xls) - Spreadsheet data for model generation
- JSON files - Structured data and configuration files
- PDF files - Documentation and diagrams to extract information from
- Markdown files (.md) - Documentation and text-based model descriptions

### output/
The `output/` directory contains files generated by EAModeler tools:
- PDF files - Generated reports, diagrams, and documentation
- CSV files - Exported data tables and model information
- JSON files - Structured output data and configuration files
- Markdown files (.md) - Generated documentation and reports

## Usage

### Available Tools

The current CLI commands are:
- `gen-interface-docs` — generate interface documentation with Mermaid flow diagrams
- `gen-erd` — generate Mermaid ERD or class diagrams from canonical data model CSV files
- `transfRICEFW` — transform S4 RICEFW CSV exports into MDW-FLOW-style CSV output
- `mdw-ricefw-diff` — compare `MDW-FLOW` and `RICEFW` inventories and produce a Markdown diff report

### Interface Documentation Generator

Generate interface documentation from CSV data with Mermaid diagrams:

```bash
# Generate target-side documentation for one application and country
uv run eamodeler gen-interface-docs input/MDW-FLOW.csv APP_0100 --direction target --country UK

# Generate all interfaces for an application across all countries
uv run eamodeler gen-interface-docs input/MDW-FLOW.csv APP_0100 --direction all --output-dir output

# Same command via the helper script
./run.sh eamodeler gen-interface-docs input/MDW-FLOW.csv APP_0100 --direction source --country FR
```

Features:

- Generates Mermaid.js flow diagrams
- Creates detailed interface tables with descriptions
- Supports `--direction source|target|all`
- Handles various CSV encodings
- Optional country-based filtering with validation
- Enhanced output with country-specific statistics
- Connected applications summary table
- Interface short descriptions included

For example outputs, see the generated Markdown files in `output/`.

### ERD and Class Diagram Generator

Generate Mermaid.js Entity Relationship Diagrams (ERD) or Class Diagrams from canonical data model CSV files:

```bash
# Generate ERD for specific data domains
uv run eamodeler gen-erd input/classes.csv input/attributes.csv input/relationships.csv "Site" "Customer & Contract"

# Generate Class Diagram for a single domain
uv run eamodeler gen-erd input/classes.csv input/attributes.csv input/relationships.csv "Finance" --diagram-type classDiagram

# Multiple domains with custom output directory
uv run eamodeler gen-erd input/classes.csv input/attributes.csv input/relationships.csv "Site" "Finance" "HR" --output-dir custom_output
```

Features:

- Generates Mermaid.js ERD and Class diagrams
- Filters data model by specified domains
- Supports multiple cardinality types (1:N, 1:1, N:M)
- Automatically sanitizes names for Mermaid compatibility
- Primary key identification and sorting
- Comprehensive error handling and validation
- Entity summary tables with statistics
- Multiple CSV encoding support

### RICEFW to MDW-FLOW Transformer

Transform S/4 `RICEFW` interface exports into an `MDW-FLOW`-style CSV for reuse in downstream analysis and documentation.

```bash
# Write `{input_stem}_output.csv` next to the source file
uv run eamodeler transfRICEFW input/S4RICEFW.csv

# Send the transformed file to the output folder
uv run eamodeler transfRICEFW input/S4RICEFW.csv --output-dir output
```

Use this when you need to normalize an S4 `RICEFW` export before generating docs or comparing inventories.

For more details, see `docs/transfRICEFW.md`.

### MDW vs RICEFW Diff

Compare `MDW-FLOW` and `RICEFW` interface inventories and generate a Markdown reconciliation report. This is the main new addition in this branch and is useful for identifying matched interfaces, MDW-only extras, and RICEFW-only gaps.

The report groups IDs into:
- `OK` — IDs present in both files
- `EXTRA` — IDs present only in `MDW-FLOW`
- `MISSING` — IDs present only in `RICEFW`

By default, `RICEFW` is treated as the reference/source of truth.

#### Filters applied

| Source | Default behavior (`--all`) | New-only behavior (`--new`) |
|---|---|---|
| `MDW-FLOW` | Keep rows where `Reference = RICEFW` | Keep rows where `Reference = RICEFW` and `New/Review = New` |
| `RICEFW` | Keep rows where `RICEFW  Type = Interface` | Same |

#### Required columns

| File | Required columns |
|---|---|
| `MDW-FLOW` | `New/Review`, `Reference`, `INT ID` |
| `RICEFW` | `RICEFW  Type`, `ID RICEFW` |

```bash
# Default mode: compare all MDW rows that reference RICEFW
uv run eamodeler mdw-ricefw-diff input/MDW-FLOW_2026-04-03.csv input/RICEFW_2026-04-03.csv

# New-only mode: only compare rows marked as New in MDW-FLOW
uv run eamodeler mdw-ricefw-diff --new input/MDW-FLOW.csv input/RICEFW_2026-03-30.csv

# Save to an explicit report path
uv run eamodeler mdw-ricefw-diff input/MDW-FLOW.csv input/RICEFW_2026-03-30.csv ./output/custom-diff.md

# Use a custom fallback directory when no output filename is supplied
uv run eamodeler mdw-ricefw-diff input/MDW-FLOW.csv input/RICEFW_2026-03-30.csv --output-dir ./reports
```

If the output filename is omitted, the report name defaults to:

`<mdw_stem>-<ricefw_stem>-diff-<yyyy-mm-dd_HH:mm>.md`

For more details, see `docs/mdw_ricefw_diff.md` and the sample reports in `output/`.
